БЛОК 1. НОВЫЕ ТИПЫ СТРАНИЦ — главный резерв трафика
==================================================
Смысл: у нас 93 объекта, но всего ~40 индексируемых лендингов. Из тех же
данных без единого нового бассейна можно собрать +60-80 страниц под
запросы, которых сейчас не покрывает ни каталог, ни район, ни категория.
Правило для всех: генерировать страницу ТОЛЬКО если объектов >= 3-5,
иначе получим тонкий контент, как было с пустыми районами.

[ ] 1.1 Страницы городов — /city/[slug]  (ВЫСШИЙ ПРИОРИТЕТ)
    Данные уже лежат в data/regionCities.json, но используются только
    как текст в composables/useAreaStats.ts — отдельных страниц нет.
    Готовые города: Нукус, Ходжейли, Кунград, Беруни, Караузяк,
    Нукусский район (Каракалпакстан); Ургенч, Хива, Багат, Ханкинский
    район (Хорезм); Бухара, Ромитан; Чирчик, Нурафшан, Зангиатинский,
    Пскентский район (Ташобласть); Самарканд.
    Запросы: «бассейн Нукус», «бассейн Хива», «бассейн Ургенч»,
    «бассейн Бухара», «бассейн Чирчик», «basseyn Urganch» — сейчас по
    ним ранжируется только общая страница региона, то есть мы конкурируем
    сами с собой и проигрываем 2GIS.
    Что делать: pages/city/[slug].vue по образцу pages/region/[slug].vue,
    список городов вынести из regionCities.json в data/cities.json
    (id, slug, region, названия ru/uz/en, координаты центра), сгенерить
    тексты + FAQ (data/cityFaq.json, data/cityGuides.json), добавить в
    routeRules prerender и в sitemap с фильтром count > 0.
    Эффект: +8-12 страниц, где мы почти без конкуренции. Хива и Бухара
    дают ещё и туристический трафик на /en.

[ ] 1.2 Страницы удобств — /features/[slug]
    Поле services заполнено у 89 из 93 объектов, но фильтр живёт только
    в query-параметрах каталога, который canonical'ится на /catalog —
    то есть ноль индексируемых страниц под весь этот кластер.
    Делать по объектам с достаточным количеством:
      parking 79, children_zone 29, trainer 29, cafe 26, sauna 17,
      wifi 13, jacuzzi 10, bar 9, restaurant 8, sunbed 8, locker 8,
      spa 6, hotel 6, hammam 4, gym 4
    Запросы из seo-keywords.txt (раздел 11): «бассейн в Ташкенте с
    сауной», «... с тренажёрным залом», «... с парковкой», «бассейн с
    тренером Ташкент», «бассейн с горками».
    Реально стоит делать 8-10 страниц: sauna, jacuzzi, trainer,
    children_zone, bar+restaurant (одной страницей «с баром и
    рестораном»), spa, hammam, gym, parking, cafe.
    Технически: одна страница-шаблон pages/features/[slug].vue,
    фильтрация через usePools по services, текст+FAQ в data/featureFaq.json.

[ ] 1.3 Страница цен — /prices
    Цены есть у 59 из 93 объектов, это больше, чем у любого конкурента,
    и мы это никак не используем. Кластер частотный и коммерческий:
    «бассейн Ташкент цены», «бассейн Ташкент цена входа», «абонемент
    бассейн Ташкент цена 2026», «недорогой бассейн Ташкент»,
    «basseyn narxi Toshkent».
    Что на странице: сводная таблица (объект / район / взрослый билет /
    детский / абонемент / сезон), сортировка по цене, «самые дешёвые —
    топ-10», «сколько стоит в среднем», текст 300-400 слов, FAQ.
    Обязательно указать дату обновления цен — свежесть даёт CTR.
    Дополнительно: /prices/cheap («дешёвые бассейны Ташкента»).

[ ] 1.4 Сезонные страницы — /season/summer и /season/year-round
    Поле season: summer 36, year-round 57. Запросы: «летний бассейн
    Ташкент», «открытые бассейны Ташкент лето 2026», «круглогодичный
    бассейн Ташкент», «зимний бассейн Ташкент», «бассейн с подогревом».
    Частично закрыто гайдом winter-swimming-tashkent, но постоянный
    лендинг ранжируется стабильнее статьи и переживает сезоны.

[ ] 1.5 Комбинации гео + тип — /district/[slug]/[category]
    Например «детский бассейн Юнусабад», «открытый бассейн Чиланзар»,
    «крытый бассейн Мирзо-Улугбек». Генерировать только пары, где
    >= 3 объекта — по текущим данным таких наберётся 8-12.
    Это классическая схема лендингов агрегаторов, длинный хвост
    с почти нулевой конкуренцией. Делать ПОСЛЕ 1.1-1.4 и обязательно
    с уникальным текстом на каждую пару, иначе Google склеит их
    с родительским районом.

[ ] 1.6 «Открыто сейчас» и «рядом со мной» — /open-now
    В pools.json заполнено schedule у 89 из 93 объектов и координаты у
    всех — можно показать, что открыто в данный момент, и отсортировать
    по расстоянию через geolocation.
    Запросы: «бассейн открыт сегодня Ташкент», «бассейн работает в
    выходные Ташкент», «бассейн рядом со мной», «pool near me Tashkent».
    Плюс сильный поведенческий фактор: страница полезна на мобильном,
    а мобильный трафик у нас основной.

[ ] 1.7 Специальные аудитории (когда появятся данные)
    Запросы есть, данных нет: «бассейн для женщин Ташкент» (женские
    часы / только для женщин), «бассейн для беременных», «грудничковое
    плавание», «школа плавания Ташкент», «25-метровый / 50-метровый
    бассейн» (poolLength заполнен только у 15 из 93!).
    Сначала дозаполнить поля (см. блок 3), потом делать страницы.
    Школы плавания — отдельный крупный кластер: born2swim у нас уже
    7 объектов, из них 6 не проиндексировано.

[ ] 2.4 Разобраться с /en (сейчас это балласт)
    В docs/site-not-indexed.txt из ~66 непроиндексированных URL больше
    30 — это /en/*. Причина понятна: translations.en.description
    заполнен у 3 объектов из 93, остальное — фолбэк на русский текст,
    то есть Google видит дубли.
    Два варианта, выбрать один:
      A) закрыть /en/catalog/* в noindex до заполнения описаний,
         оставив в индексе только /en главную, /en/catalog, /en/guide —
         перестанем тратить краулинговый бюджет;
      B) заполнить en-описания топ-30 объектов (Ташкент + Бухара +
         Хива — туристические, там en реально ищут).
    Рекомендую A сейчас + B постепенно для туристических городов.
    То же по uz: описания заполнены у 3 из 93 — но uz важнее en для
    нашей аудитории, его заполнять в первую очередь (задача 15).

[x] 2.5 Три ташкентских бассейна вне районов — РЕШЕНО ИНАЧЕ (05.08.2026)

    Районы проставить было нельзя: по адресам это Юкоричирчикский,

[ ] 4.7 lastmod в sitemap
    В data есть createdAt у каждого объекта; в sitemap отдаются только

[ ] 4.8 WebSite + SearchAction в schema на главной
